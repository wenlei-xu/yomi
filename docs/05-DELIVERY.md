## 1. 本版交付范围
从空工程到可安装、可配置、可用可控模型聊天、可恢复数据的应用一次做完，没有把一条演示流程当作整体完成。需要真实凭证、真机与 release 签名才能验证的项没有完成，已在 §2、§4.2、§10 明确标注。
本版范围排除了资料库、工作功能、向量记忆、剧情状态、图片/语音聊天、云同步和 iOS 正式发布。iOS 只保留共用核心与 schema 的可实施性说明，不用未验证的源码冒充交付。
没有真实模型凭证、真机和发布签名材料，因此这些项停在“未验证”，在 §4.2 与 §10 逐条列出，不用 fixture 结果替代。

## 3. 内部实施顺序

实现按依赖顺序一次完成：工程与 Android 壳 → schema 与 repository → model protocol 与原生 SecureVault → runtime 与 tools → 四入口 UI → 备份导出 → 构建。没有分阶段对外交付。

## 5. 必需故障与并发矩阵

原设计定义 F01–F40 共 40 项故障注入。本版**没有执行**这套矩阵，只做了下面 4 项手工验证：

| 用例 | 实际做法 | 观察结果 |
| --- | --- | --- |
| 停止 | Aster 等待 mock 响应时点停止 | 只有 Aster 的请求到达服务端；无回复、无 Beacon/Cypher 请求；会话转 paused |
| 重启恢复 | 停止后 force-stop 再启动 | 历史、paused 状态、“继续”按钮都在；继续后重新生成 |
| 轮边界 | 首轮进行中插入第二条用户消息 | 首轮请求只含首轮内容，无下一条用户消息；第二轮含两段历史 |
| 后发言可见 | 三人群按序发言 | Beacon 看到 Aster 的本轮回复；Cypher 看到前两条 |
## 6. 多 Agent 行为矩阵
以下每项都先用可控模型证明控制机制，再用真实模型观测对话质量。真实模型可能存在随机性，报告每次结果和成功率，不删掉失败样本。
| 场景 | 预期行为与观测 |
| --- | --- |
| B01 用户单聊/问候/emoji | 能及时回应，不被 triage 当空工作吞掉 |
| B02 三角色群开放问题 | 能形成有内容回应；允许沉默，不要求每人一条 |
| B03 点名一个/多个角色 | 被点名角色有机会回应，其他角色不过度抢答 |
| B04 明确要求大家各说一句 | 模型理解要求；系统仍不硬编码固定轮询 |
| B05 接龙/数数/轮流故事 | 后回应者读取已完成新回复；无竞态造成的完全重复 |
| B06 成员不回应/连接失效 | 其余角色能自然推进，不无限等一个角色 |
| B07 用户生成中补充/纠正 | 安全 steer 后新内容生效，不继续答已经撤回的旧问题 |
| B08 两群同时聊天/同角色跨群 | 串行但公平；人设稳定，私有上下文不串房间 |
| B09 角色间私聊/建小组 | 权限、来源、旁观与根预算正确，成员不被偷偷授权旧历史 |
| B10 无实质内容的互相赞同 | 自然结束或预算暂停，不永远烧 token |
| B11 长聊天压缩/记忆召回 | 人设与近期事实保留，记忆按 scope 正确注入 |
| B12 清记忆/删来源后追问 | 不继续从已失效摘要回忆被删内容 |
| B13 重试部分已成功的互动 | 已提交效果可见，不无条件重新发布全部回复 |
| B14 停止/切后台后等待 | 零新本地发言；重开不自动恢复外部调用 |
v1 最少覆盖 2、3、6 个角色规模；8 个角色做压力/队列测试。真实模型报告至少记录协议/端点别名、模型 ID、上下文配置、角色数、提示词版本、运行次数、成功/失败分类、调用数、token、耗时。敏感地址/Key 不写入共享报告。
若只有一个可用协议的真实端点，另一个协议必须完成可控契约和原生传输验证，并明确标“真实端点待验证”；不能宣称所有服务商兼容。
## 7. UI 与原生场景矩阵

模拟器上逐页确认：四入口、建群、导入角色、记忆面板、连接表单与测试、用量列表、备份导出、清空。未做：TalkBack、字体放大、横竖屏、外接键盘、深浅主题、reduced-motion、系统返回边界、文件选择取消与权限拒绝。
## 8. 性能与规模

原设计的 10 项性能基准（冷启动 p95 ≤ 3s、分页 ≤ 200ms、20,000 条滚动虚拟化、8 角色突发、100 MiB 备份等）**本版未测量**。已实现的规模约束：消息分页 50 条、inbox 查询上限 60、上下文 36 条、摘要源 400 条、搜索 100/30 条、单次响应 8 MiB、群成员上限 9、头像 2 MB。

没有虚拟列表；单页 50 条消息全量 DOM 渲染。未做大数据量压测。

## 10. 最终完成判据与本版结论

原设计的完成判据要求真实模型验证、真机验证、release 可复现和完整故障矩阵。**这些都没有完成**，因此本版不声称达到原设计的“完成”标准。

本版实际交付的是：**功能完整的 Android v1 debug 可安装版本**。四导航、角色、单聊、群聊（第一轮简单规则）、角色私聊旁观、文字记忆、模型连接与 Keystore 凭证、内置工具、activity 预算、停止与重启恢复、搜索、备份恢复、导出都已在模拟器上用可控模型走通。

对外声明必须保留的限制：

- 真实模型行为未验证；不同服务商对工具调用的支持程度可能不同，可能出现“模型没有按要求完成本轮发言”。
- 只有 debug 签名；不要对外分发。
- 当前导出使用加密 `.yomi`，恢复校验后在 SQLite 事务中替换；历史快照中的明文/半清库描述已过时。
- 没有 iOS 构建，没有真机记录。
- 当前未点名群聊包含辅助路由（全员回复或单一主答）、主答失败后的持久交接以及角色沉默判断；与 Cumora 的完整实现仍需持续逐项对照。
- 长会话无虚拟列表；无深/浅主题与无障碍验证。
