# 持久调度、限速与人工恢复

日期：2026-10-23。此记录补充 docs/09–10 的调度缺口，完整 App 目标继续保持进行中。

## 本次实现

- schema v7 新增 `agent_turn_limits` 和 `retry_jobs`，均受角色/会话/运行的外键生命周期约束。备份只包含长期聊天事实，恢复后不导入旧重试任务。
- 每角色每 60 秒最多启动 30 次自主处理。用户消息、用户表情互动、手动继续/重试不消耗这项自主限额；不同角色互不抢占该窗口。
- 自主限速后，inbox 转 deferred，保存到期时间并释放 Agent 队列；等待期间可让其他会话工作，不阻塞串行队列睡眠。
- 已知 HTTP 429/500/502/503/504 在本次尚未执行任何工具或发言时，可进入持久重试。保留原有单次请求至多两次立即重试，额外最多两轮延后重试，间隔 5 秒、10 秒；每轮仍至多三次实际请求，连续失败最坏共九次，全部计入 activity 的 64 次请求预算。
- 401/403、未知网络结果、协议错误、有工具调用或发言的处理不自动延后重试。用完次数则转 dormant，等待人工决定。
- 到期派发再次验证会话 epoch、暂停、成员角色启用/归档及资料版本、activity 状态和预算；不符合条件时暂停，不偷偷创建新预算绕过约束。
- 等待中的会话在聊天页显示等待提示和停止入口；全局停止也包含等待任务。会话停止沿已有因果链取消相关重试，后台清除计时器并停止等待会话。
- 重启、WebView 新运行时、数据维护将 pending/dispatched 任务置为 dormant，不自动重放。手动重试/继续/忽略会终结旧任务，按用户的新决定处理。
- 新用户消息替代旧的自动重试；同一发送命令的幂等重放有显式标记，不误清除已经安排的等待计时器。
- 同一角色后续成功后不再保留旧失败恢复卡；不同角色尚未解决的失败仍可显示，每个会话最多一张恢复卡。

## 相关正确性修复

用户对已处理消息添加表情，会重新唤起对应 inbox；处理请求明确带有“用户的表情互动”，不再只依赖旧消息作者类型。删除反应不唤醒，角色自己的反应不继续制造循环。加入前的消息不会因用户反应而进入新成员 inbox。

没有触发消息 activity 的人工继续使用当前会话的新根预算；自动派生处理仍继承触发消息的 activity。创建私聊时的来源关系不再用于决定后续所有预算归属，手动继续复用的私聊也不会取消创建来源群的独立互动。

主模型账本统一由实际请求入口记录。退避期间取消或预算预留失败不会再虚构一条未发出的模型请求；工具执行失败也不会把同一次已完成响应再记为第二条失败请求。
