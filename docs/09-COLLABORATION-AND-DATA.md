## 本次实际落地

| 需求 | 当前实现与证据 |
| --- | --- |
| 群聊路由 | 未点名时辅助模型判断 each / one-of-us，后者选择有效成员为主答；不确定或错误回退 each。结构化点名优先，@all 保留全员机会。角色仍可根据内容沉默。 |
| 自主判断 | 人类消息进入主处理；角色间群消息做 actionable 判断，一对一每 8 个消息序号检查一次；连续纯角色消息到 20 条停止。辅助失败保守停止角色间续聊。 |
| 生成中补充 | 生产群聊使用实时上下文，hop 边界在完整工具结果之后注入有界新消息；旧稿提交遇新内容会 HELD。显式 roundMessageId 读取只保留为严格边界能力，不再代表生产群聊策略。 |
| 模型配置 | 角色主、辅助判断、摘要分别可覆盖全局默认；未设置按用途继承。角色编辑器已有入口；复制角色保留模型配置，不复制聊天和记忆。备份包含配置。 |
| 公平排队 | 同 Agent 跨房间串行；人类优先于纯角色工作，等待时间提高优先级；会话停止移除待执行任务。全局模型请求最多 4、每连接最多 2。 |
| 有界重试 | 尚未执行任何工具或发言时，对 HTTP 429/500/502/503/504 最多重试两次，退避 500/1000ms，可取消且计预算。认证错误、未知结果、已经有副作用不自动重试。 |
| 因果链 | run_causes 保存一次运行消费的消息。复用私聊从触发消息继承 activity，禁止旧取消/耗尽消息另开预算。停止沿实际消息→run 因果链取消，创建来源只作为溯源。 |
| 记忆来源 | memory_sources 关联自动记忆的已读消息；工具可显式选来源，未指定时保守关联最近 6 条可见消息。删除或清空来源通过 SQLite 触发器使记忆失效；设为全局保留来源。人工编辑将其转为人工记忆并解除自动来源关联。 |
| 加密备份 | 新导出为 .yomi：PBKDF2-SHA256 310000 次、随机 16 字节 salt、AES-256-GCM、随机 12 字节 IV、128 位认证标签。旧明文 v2 JSON 仍可导入。界面录入密码，成功后清空输入，不持久保存密码。 |
| 恢复检查 | 完整性字段、唯一人类身份、已知列与标量类型、会话来源无环、外键、next_sequence。拒绝错误密码或篡改文件；SQL 检查失败整笔回滚。允许子会话在文件中先于父会话。 |
| 维护隔离 | 导入/全部清空先阻断新命令，等待已接受命令，再取消并等待旧 Agent 和队列结束。替换期间不唤醒；完成后不重放旧任务。成功恢复后清除原机相关凭证，必须重新录入 Key。 |
| 手机隐私 | 关闭 Capacitor 桥接日志，避免正常桥接把 SQL 参数写进日志；关闭 Android 系统自动备份与设备自动迁移，保留用户主动导出。 |

辅助判断无效 JSON 曾在同次调用里同时记录 completed 与 failed，现已改为一条 failed。turn_finish 的说明已与群聊可沉默规则统一。

## 升级与交付证据

- schemaVersion 6；v4 增加 agent_model_bindings，v5 增加 run_causes，v6 增加 memory_sources 和删除失效触发器。跳过未安装中间版本可直接升级，不清空聊天、角色和人工记忆。
- 备份 payload 保持 yomi-backup v2，新增 agentModelBindings、memorySources 为可选字段；外层加密容器独立为 v1。临时 runs、run_causes 不导出。
- `npm run typecheck` 通过。
- `npm run test:agent -- --report`：29 项关键回归通过。使用真实 TS Runtime、Repository、SQLite SQL/事务，模型由本地替身提供；详见 `08-AGENT-REGRESSION-RESULTS.json`。
- `npm run android` 通过，debug APK 已 `adb install -r` 到 emulator-5554 并启动。
- 模拟器实际迁移记录 2、3、5、6，SQLite 3.43.1，integrity_check=ok，foreign_key_check 无记录；两个记忆失效触发器存在。
- 模拟器设置页实际导出和通过文件选择恢复加密备份成功，WebView 的 WebCrypto 可用；测试文件只包含空库与本地身份，没有 API Key。
- Android 包信息无 ALLOW_BACKUP 标志；现有四导航保留。
- 修复聊天刷新覆盖未落盘草稿；草稿只在进入会话时加载，引用可从旧历史恢复。发送失败重试保留命令 ID，同步锁避免同一事件间隙重复提交。模拟器验证刷新保留未保存文字、重复 commandId 仅入库一条消息，临时测试角色和会话已删除。
- 修复 WebView reload 后 JS 连接表丢失、原生句柄残留导致 Connection already exists 的启动错误。SQLiteConnection 由模块统一持有，open 前核对原生连接；createApp 共用初始化 Promise。实际模拟器 reload 后四导航正常，无启动失败。
- 本轮构建与安装证据、APK SHA256 见 `09-DELIVERY-EVIDENCE.json`。

## 尚未完成，继续保留在目标中

1. 恢复目前使用当前库内的完整事务，具有 SQLite 崩溃回滚保障；尚未实现原设计要求的独立 staging 数据库、切库 manifest/journal、上一版库回退入口。不能把“没有 staging”误写成“事务失败会半清库”。
2. 调度尚无 Cumora 对应的每 Agent 时间窗口限速、持久重试队列、完整路由认领/交接。当前内存排队、有限请求重试与人工恢复不等价于这些机制。
3. HELD 使用运行内实际已见边界和事务提交检查，未照搬 Redis 的 TTL/确认令牌协议；内部网络仍整包返回，无 SSE。原设计的长工具历史压缩还未完成，当前超预算会明确失败。
4. v6 之前未记录来源的自动记忆无法补出可靠依赖。新记忆来源受追踪；旧记录不能据此声称都具备来源失效保证。
5. 长列表虚拟化、完整外观/文字大小/无障碍、维护与诊断导出、发布签名与许可证整理等原设计条目仍需收口。docs/05 的历史 verified 不能替代当前逐项证据。
6. 按用户要求未扩展真实模型、真机或完整故障矩阵，不以本地替身和模拟器记录冒充这些实测。

向量记忆、CLI/工作工具、云端常驻、iOS 正式交付是本轮明确排除的内容；以上未完成项不是这些排除项。
