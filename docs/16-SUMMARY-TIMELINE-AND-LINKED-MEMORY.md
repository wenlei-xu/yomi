# 摘要时间线与会话记忆关联

版本：1.0.2 / versionCode 3 / schema 13。需要完整 APK 升级；此次新增关联表和摘要字段，不使用旧版网页热更新包。

## 入口

聊天标题 → 会话资料 → 摘要时间线与会话关联。按角色查看和设置，四个主导航保持现有结构。

## 摘要时间线

- 自动整理仍从消息序号达到 80 后开始，保留最近 24 条左右的原文；模型请求沿用摘要模型及原有调用预算。
- 同一次摘要请求返回最新累计摘要和本次新增消息段的摘要，不增加额外模型请求。按消息区间持久保存每次结果；同一覆盖末序号再次整理时更新对应条目。每页 20 条，可加载更早记录，展开可看当时的累计摘要。
- 提示只注入最新一份有效累计摘要，并明确覆盖区间，不把历史累计快照重复注入。
- 旧库现存的累计摘要继续保留为“累计快照”。此前已经删除的历史版本不能重建；之后的新结果逐段积累。不返回结构化结果的兼容线路仍可保留纯文字累计快照，不伪造分段内容。
- 修改原消息、调整人设或成员后，旧快照保留供查阅，并按有效标记、消息修订和可见范围显示状态；失效结果不供模型使用。清空或删除会话会清除相应时间线。

## 会话关联

- 在目标会话里选定角色，勾选来源会话并单独保存。方向为“来源 → 目标”；每个角色在每个目标里最多 8 个来源。需要反向引用时，在另一会话单独设置。
- 只允许选择同一角色当前参加的来源与目标。给 A 的关联不会直接注入 B 的请求；不会读取其他角色的记忆或群成员私有备注。
- 每次生成动态读取该角色在来源里的最新有效摘要、最多 4 条会话记忆，以及摘要之后最近 6 条可见消息。短会话尚无摘要时仍能通过最近消息提供背景；每个来源分摊有限上下文预算。
- 消息按角色入群边界过滤；已删原文不读取，撤回只保留撤回事件。离开来源或目标后，关联立即失去读取资格；删除会话时关联级联删除。
- 不递归读取来源的关联，不复制成全局记忆，因此双向或循环关联不会无限放大。取消关联停止之后的自动引用，已有聊天和角色已记录的记忆仍是独立数据。
- 保存关联会更新角色配置版本。工具提交事务会重新检查来源关联、成员可见范围、消息修订及已读取记忆版本，阻止来源在生成期间被修改、撤销或删除后的旧资料继续提交。
- 重新生成的新分支不继承会话关联。用户可以在分支里手动建立关联，界面提示这会引入来源的当前背景。
