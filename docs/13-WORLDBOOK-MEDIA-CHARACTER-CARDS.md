# 世界书、多媒体与酒馆角色卡

本轮在现有四个导航入口中加入功能，数据库 schema 升至 11。会话备注、主动互动和模块备份继续保留。

## 使用入口

| 功能 | 入口 | 行为 |
| --- | --- | --- |
| 世界书 | 我 → 世界书 → 管理 | 创建、编辑、停用、删除卷与条目；JSON 导入和导出 |
| 会话绑定 | 聊天标题 → 会话世界书 | 同一卷可绑定多个聊天；取消绑定保留卷和条目 |
| 角色绑定 | 角色 → 编辑资料 → 角色世界书 | 多选已有局部卷并单独保存；支持撤销未保存的选择、解除绑定和管理卷；新角色先保存后进入编辑 |
| 多媒体配置 | 我 → 多媒体设置 | 分别选择生图、语音连接及模型，可新增专用连接 |
| 生图、语音、表情包 | 角色 → 多媒体；聊天输入区的加号 | 生成、预览、保存；从聊天入口可发送媒体及表情包 |
| 消息朗读 | 角色消息内的“朗读” | 语音合成并提供播放器；支持取消 |
| 酒馆卡 | 角色 → 导入酒馆卡 | V1 JSON、V2/V3 JSON、PNG；导入结果提示兼容范围 |
| 原卡 | 角色 → 编辑资料 → 酒馆角色卡 | 查看保留说明，导出导入时的原始 JSON/PNG |
| 开场白 | 空的角色单聊 | 选择主开场白或备用开场白；不会自动开启模型调用 |

## 世界书

- 全局卷对全部聊天生效；局部卷可绑定会话或角色。角色绑定用于该角色参与的全部聊天，只提供给对应角色；同一卷可复用到多个角色。角色卡附带的卷同样显示在角色绑定列表中，可以解除或重新绑定。
- 角色绑定单独保存，解除绑定保留世界书内容与其他角色的绑定；停用卷保留关联但不注入。全局和会话范围仍独立生效，同一条目不会因多处绑定重复注入。保存前验证角色和全部所选卷，失败时保留原关联；实际变更会更新角色配置版本，阻止旧配置的运行继续提交。复用现有 `lorebook_actor_links`，不增加 schema 版本；完整备份、ZIP 世界书模块和角色复制继续携带关联。
- 常驻条目始终参与候选；关键词条目扫描最近 12 条可见消息，支持附加关键词、大小写和顺序。
- 候选依次装入最多 2048 个估算 token，且不超过配置窗口的 12%。放不下的条目整条略过；角色人设、记忆、摘要和消息仍受总上下文检查。
- 在每次模型调用前使用已提供给本次请求的消息边界解析，避免未见消息或其他角色的专属设定被提前注入。
- 世界书只注入一次，作为背景资料。保持既有工具循环和消息权限。
- 酒馆递归扫描、概率触发、正则、特殊注入位置及扩展脚本尚不执行；角色卡原始字段和导入条目的原始 JSON 仍保留。

## 角色卡与数据保留

使用规范中的 UTF-8 → base64 PNG tEXt 元数据，优先读取 `ccv3`，其次 `chara`。图片和 JSON 都在本地解析，不执行导入脚本，不请求卡片内的外部地址。

角色描述、场景、对话示例映射到人设；性格映射到说话风格。开场白及备用开场白单独选择。支持替换 `{{char}}`、`{{user}}`。卡片的系统提示、历史后指令及其他宏保留在原卡中，不接管 App 的运行指令。

导入在单个数据库事务内创建角色、原卡和内嵌世界书；任一部分无效时回滚。`character_cards` 保存完整原始 JSON、原始 PNG 和兼容说明，包括未知字段、作者和扩展。复制角色、Yomi 角色导入导出和完整备份均保留原卡。原卡导出返回导入时的数据；后续 Yomi 资料修改保存在 Yomi 角色导出和备份中。

参考：[V2 规范](https://github.com/malfoyslastname/character-card-spec-v2/blob/main/spec_v2.md)、[V3 规范](https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md)、[SillyTavern PNG 解析](https://github.com/SillyTavern/SillyTavern/blob/release/src/character-card-parser.js)。实现独立编写。

## 多媒体

- 生图走用户配置连接的 `/images/generations`，第一版接收 base64 图片。图片、语音分别配置模型，不继承聊天模型 ID。
- 语音为文字合成和消息朗读，走 `/audio/speech`，采用 MP3。当前不包括录音识别、实时语音通话或声音克隆。
- 原生桥对音频做二进制安全的 base64 传输，错误响应仍以文本处理。API Key 继续由原生安全输入和凭证容器管理。
- `media_assets` 保存元数据，`media_blobs` 保存数据；消息仅引用 ID。重开聊天后仍能播放、预览，完整备份包含二进制内容。
- 表情包在发送时创建媒体快照；删除表情收藏不破坏历史消息。角色可用 `sticker_list` 和 `message_send.stickerId` 发送本机表情。
- 历史媒体向文字聊天模型提供描述，不包含图片视觉理解能力。
- 取消、离开前台和数据替换会取消相关媒体请求。未完成的生成重启后标为中断，等待手动重试。失败时保留可读原因，不插入伪成功消息。

## 迁移与检查

旧库按列增量迁移。旧版会话专属世界书转换为可复用卷，同时保留会话绑定。旧消息和角色保留。完整备份增加世界书、原始卡、媒体、表情及多媒体配置；继续支持旧版本备份，API Key 不导出。

`node scripts/check-roleplay.cjs` 包含世界书 CRUD/范围/预算、手动角色绑定的跨聊天生效与同群角色隔离、多卷及非法选择回滚、停用/解绑/重复注入/复制和备份恢复、角色卡未知字段、PNG Unicode 元数据、原子导入、开场白、表情快照、未来消息边界、旧表补列、图片和二进制音频响应检查。检查仅使用内存数据库和模拟网络。

Android 构建命令：`npx cap sync android`，然后在 `android/` 中运行 `gradlew.bat assembleDebug`。真实服务商和真机音频播放尚未联调，需配置对应 API 后确认；本轮不把模拟响应计作真实模型验证。
