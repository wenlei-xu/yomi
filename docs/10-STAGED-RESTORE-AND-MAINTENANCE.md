## 数据版本与切换

`src/data/store.ts` 使用独立 `yomi_catalog` SQLite 数据库保存当前数据版本、上一版本、待导入版本和准备阶段。数据仍使用 schema v6；目录库与聊天数据库独立提交。

恢复过程：

1. 通过既有维护屏障阻断新写命令、取消旧请求并等待 Agent/队列结束。被中断任务明确记为 interrupted，原库保留时可人工重试。
2. 先在目录库持久记录新版本名及 building 阶段，然后在新的 `yomi_store_<随机ID>` 数据库中导入备份。
3. 暂存库完成原有字段/身份/外键/序号检查、事务提交和 quick_check；记录 prepared 阶段。
4. 在目录库的一笔事务中切换 active/previous 指针。崩溃后只能读到提交前或提交后的完整指针。
5. 原 Repository 持有的 Database 对象在队列边界接管新连接，旧连接关闭，上一份数据文件保留。
6. 只有不再被 active/previous/pending 引用的旧版本进入持久清理队列；清理失败保留队列，可再次处理。

未提交的 building/prepared 记录在下次启动时被撤销，原 active 数据保留；已提交的新版本若缺失或无法通过检查，会尝试打开上一版本并记录明确回退提示。两份均不可用时显示启动错误，不擅自新建空库掩盖故障。

首次升级沿用已有 `yomi` 数据库，不搬动或清空历史。目录库首次创建后才允许创建全新的初始数据文件；已有版本缺失不能当作首次安装。

“我 → 数据与备份”可切回上一份数据，当前版本随之变为回退副本；也可单独删除回退副本。全部清空同时清理保留版本，避免旧数据经回退入口重新出现。

Android 删除旧数据库使用受名称白名单限制的原生私有文件操作，不要求先成功打开可能损坏的 SQLite 文件。目录库名称不在可删除名单内。JS 层首先排除当前、上一和待导入版本，且先关闭对应连接。

## 维护与诊断

- 存储页展示当前数据库页大小、可回收页、消息/角色/会话/有效记忆/运行记录数量；保留版本单独存在，不把当前库大小说成整个 App 占用。
- 清理已结束的模型调用及工具动作，保留正在运行任务的幂等记录、聊天、角色、记忆和因果 run 记录。清理会减少用量统计，界面明确告知。
- 数据库压缩经维护屏障执行 VACUUM，不把 VACUUM 放进普通写事务。中断任务仍可由用户重试。
- 用量通过 SQL 聚合整个保留账本，按主回复/辅助判断/摘要分类；最近记录展示上限不再限制总数。未知输入或输出单独计次，不当作零用量。
- 导出的诊断只含版本、数量、协议、配置窗口、状态、受限错误码及用量/时间；不含消息或记忆正文、角色姓名/人设、模型地址、模型ID和 API Key。
- 本地资料输入增加编辑保护，运行刷新不会覆盖尚未保存的昵称/简介。
